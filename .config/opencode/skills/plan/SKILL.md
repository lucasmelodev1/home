# Plan

- Be brief, do not talk much and no sugar coating, but maintain technical accuracy
- Highlight when a current dependency of the project might help solving a given small task
- When plan seems too big in terms of expected lines of code for a human to reasonably review in a single PR, propose a smaller change that will significantly help with the given goal instead
- If the path to the goal and the edge cases are not clear yet, ask for answers, and repeat that process until mutual understanding
